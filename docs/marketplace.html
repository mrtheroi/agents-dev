Setup

Once per machine you add the marketplace and install your stack. You never clone this repository — Claude Code caches it in ~/.claude/plugins/cache/ and runs offline.

1

Add the marketplace

By its remote URL. No manual git clone.

/plugin marketplace add https://github.com/mrtheroi/agents-dev
2

Install common + your stack

Everyone installs common; then just their stack's plugin.

/plugin install common@claude-dev-agents
/plugin install python@claude-dev-agents
/plugin install laravel@claude-dev-agents
3

Auto-update for a whole team · optional

Third-party marketplaces ship with auto-update off. To force it for every machine, deploy this to the managed settings file or via the Claude.ai admin console. Path per OS: /Library/Application Support/ClaudeCode/managed-settings.json (macOS), /etc/claude-code/managed-settings.json (Linux), C:\ProgramData\ClaudeCode\managed-settings.json (Windows).

{
  "extraKnownMarketplaces": {
    "claude-dev-agents": {
      "source": { "source": "url", "url": "https://github.com/mrtheroi/agents-dev" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "common@claude-dev-agents": true
  }
}

How it works

The repository is a Claude Code marketplace: a catalog that lists plugins, one per stack. Distribution and updates are native — project repos copy nothing.

The distribution flow

claude-dev-agents
central git repo · source of truth
→
~/.claude/plugins/cache
Claude Code clones & caches it · runs offline
→
your project
stays clean · no copied scripts or .claude/agents

The model

The unit of installation is the plugin, not the single agent. Installing one brings all its subagents, but they are invoked on demand from their description — an agent that doesn't apply uses no context. To silence one, a deny: ["Agent(name)"] in settings is enough.

Updates are gated by each plugin's version: you bump it and push, and the team gets it via /plugin marketplace update or, if enabled, auto-update. Per-project state lives in the project's own repo and never mixes between clones.

Two layers: universal standards + stack specialization

Design patterns, architecture and review standards are universal; only language and project particulars differ. So they live in two layers — written once, never copy-pasted across stacks.

common/standards
universal layer · review doctrine, engineering principles, the subagent contract
+
<stack>/agents
specialization · only this stack's particularities (SQL injection, brand tokens, framework idioms…)
→
composed agent
one self-contained file Claude Code loads at runtime

Subagents run in an isolated context with no import mechanism, so each must be a single self-contained file. An agent pulls in a standard with a directive — <!-- @include plugins/common/standards/code-review.md --> — and scripts/compose-agents.mjs expands it in place (substituting the agent's name). It is idempotent and ships a --check mode for CI; build-catalog.mjs runs it automatically.

The payoff: edit a standard once and every stack's agent inherits the change on the next compose — no drift between the reviewers of different stacks. Each stack file stays short, holding only what is genuinely particular to it.
